# ADR-001: archived_at flag over status enum or archive-root reparent  [status: accepted]

Archive is a nullable `nodes.archived_at` timestamp with cascade mutations — not a new node status, not a structural reparent. Spec: archive-rebalance (2026-07-23).

- **Context:** Three mechanics were viable for soft-hiding finished work. `NodeStatus` is PENDING/RUNNING/DONE/BLOCKED/FAILED with DONE write-once terminal (`src/milknado/domains/common/types.py:40`); the nodes table has no CHECK constraint, so a new status needed no DB migration but wide code churn (VALID_TRANSITIONS, display colors/icons, the MCP `_parse_todo_status` boundary parser in `src/milknado/mcp/_core.py`, every status-filtered query). A synthetic Archive root needed no schema change at all but bends `VALID_CHILD_KINDS` (`types.py:56`) and leaves harvest/wiki/github exporters walking archived subtrees. The MIGRATIONS framework (`src/milknado/domains/graph/_persistence.py:50`) had already landed, making a column add cheap.
- **Decision:** Nullable `archived_at` column (migration v3) plus `archive_subtree`/`unarchive_subtree` cascades in `_mutations.py`; invariant *archived ⇒ whole subtree archived*; status machine untouched.
- **Alternatives:** ARCHIVED status — wider churn, DONE loses write-once terminality, no reversibility advantage. Reparent under Archive root — structural fiction, containment bending, exporters still walk it (rejected-directions archive-rebalance-001/002).
- **Consequences:** Every forest walk in `_reads.py` gains `include_archived=False`; harvest (`src/milknado/domains/reporting/harvest.py:57`) MUST pass True or wiki export silently stops — pinned by an acceptance criterion and test. Unarchive refuses under an archived ancestor; add/move under an archived parent refuses.
